# Mason v0.23.1

**`mason user check` says whether a password is a user's, for a sign-in page of your own in front of Mason.** A
project pinned to 0.23.0 runs on 0.23.1 as it is, and no table is read again ("Before you upgrade").

## Before you upgrade

- **No table is read again.** To see this for your own project, run `npx @mason-data/cli@0.23.1 upgrade --check` in
  the project's folder while Mason 0.23.0 runs. It lists each table the first start reads again, and changes nothing.
- **The pin needs no change.** Before 1.0 the command and the image run a project pinned to their own minor version,
  at their own patch or an older one, so 0.23.1 runs a project pinned `version: 0.23.0`. Moving it to
  `version: 0.23.1` in `mason/mason.yml` is optional. Once you do, a 0.23.0 command or image refuses the project, so
  move it only once everyone and everything that runs the project has 0.23.1. A project `mason init` makes on 0.23.1
  is pinned 0.23.1.
- **On Mason Cloud, upgrade the replica first, then move the pin.** `mason replica upgrade <org>/<name>` moves the
  replica to 0.23.1. Mason on the replica restarts, and its connections drop. It goes on running your project pinned
  0.23.0 as it is. A replica on 0.23.0 runs a project pinned 0.23.0, but not one pinned 0.23.1: `mason deploy`
  refuses that one before it sends anything, names both versions, and gives `mason replica upgrade` as a way out
  where the service offers 0.23.1. A project pinned 0.23.0 deploys to a replica on either version.

## What changes

- **`mason user check <name>` says whether a password is a user's.** It is for a sign-in page of your own in front of
  Mason.
  - It reads the password from stdin, never from the command line. At a terminal, it asks for it and does not show
    it. The password is never printed or logged.
  - It answers `ok`, `wrong`, `disabled` or `removed`, and exits 0, 3, 4 or 5. With `--json` it gives
    `{ user, answer, id }`: the user's id for `ok`, `disabled` and `removed`, and none for `wrong`. `removed` means
    the password of a user of that name that was removed, such as the old password of a user removed and added again.
  - It judges the password as Mason's Postgres listener does, but never the address a user may connect from.
  - **A page in front of it must limit attempts**: by the browser's address, by replica and by user name. `check`
    answers `wrong` as often as it is asked, so a page with no limit lets anyone guess without end.
  - **The page signs a person in on `ok` alone.** `disabled` and `removed` carry an id too, of a user that may not
    connect.
  - It reads the project's API key, from `.mason/config.json`, or `MASON_API_KEY` under `mason serve`. So the page
    runs where Mason's own files are kept, as Mason's user.
  - `mason user list` already shows each user's id. A name still bound to the same id is the same user. A user removed
    and added again has a new id.
